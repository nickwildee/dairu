# 일러스트 작업 지침

이 디렉토리에서의 작업과 대화는 저장소 루트 `AGENTS.md`의 공통 규칙을 따른다. 시작 전에 루트 지침, `PROGRESS.md`, 이 파일, 대상 스타일과 작업의 관련 문서를 읽는다.

## 역할

에이전트는 확인된 스타일과 구도로 미드저니용 프롬프트를 작성한다. 사용자가 미드저니에서 이미지를 생성해 가져오면 함께 검토하고 피드백을 반영한다.

새 일러스트 작업은 사용자가 모아 둔 참고 이미지 10장 정도를 먼저 요청한다. 이미 이미지가 있으면 받은 자료로 1~3단계를 진행한다. 사용자가 말로만 새 그림을 기획하고 싶다고 하면 설명에서 스타일·구도를 정리해 4단계부터 확인한다. 그림 없는 속지의 레퍼런스는 [속지 지침](../inserts/AGENTS.md)에 따라 다룬다.

한 번에 전달된 레퍼런스들이 모두 같은 디자인 스타일이라고 가정하지 않는다. 업로드 묶음이나 파일 순서를 스타일 분류의 근거로 삼지 않는다.

## 1. 레퍼런스 접수와 관찰

- 제공된 레퍼런스에 식별 가능한 번호를 부여하고 원래 파일명 또는 확인 가능한 출처와 대응시킨다. 기존 번호는 유지하고 새 자료에는 새 번호를 부여한다.
- 파일이 많으면 우선 전체 자료와 분량을 확인하고, 사용자가 검토하기 쉬운 분석 묶음을 제안한다. 일부만 관찰했다면 그 범위를 밝힌다.
- 원본을 보존한다. 실제 제공된 파일과 다시 접근할 수 있는 위치를 기록하고, 확인하지 않은 이미지를 보았다고 하지 않는다.
- 같은 소재와 같은 그림체를 구분한다. 같은 캐릭터나 동물이어도 스타일이 다를 수 있고, 소재가 달라도 같은 스타일일 수 있다.

## 2. 스타일 분류와 분석안 제시

다음 요소 중 실제로 관찰되는 특징을 비교한다. 요소의 목록 자체를 사용자가 원하는 디자인 요구사항으로 간주하지 않는다.

- 선: 유무, 굵기, 균일함, 윤곽의 처리.
- 색: 팔레트, 채도, 명도, 대비.
- 질감: 종이, 붓, 연필, 평면적 표현 등.
- 형태와 비율: 단순화 정도, 실루엣, 캐릭터 비율.
- 명암과 입체감: 그림자, 하이라이트, 공간 표현.
- 장식과 분위기: 반복되는 표현과 다른 스타일과의 차이.

각 분류안에는 다음을 함께 제시한다.

1. 임시 분류명과 포함할 레퍼런스 번호.
2. 같은 분류로 제안한 근거와 공통 특징.
3. 다른 분류와 구분되는 특징, 분류 안에서도 차이가 나는 부분.
4. 해석이 애매한 부분과 사용자에게 확인할 사항.
5. 사용자에게 제안하는 반영할 특징과 제외할 특징.

애매한 자료는 분류 보류 또는 복수 스타일의 특징이 섞인 사례로 제안한다. 모든 자료를 반드시 하나의 분류에 끼워 넣지 않는다. 필요한 경우 하나의 레퍼런스를 여러 분류에서 참조할 수 있으나 원본을 무분별하게 복제하지 않는다.

레퍼런스 전체를 사용자가 원하는 것으로 취급하지 않는다. 예를 들어 선과 질감만 참고할 것인지, 색감도 반영할 것인지 확인한다.

## 3. 분류별 사용자 확인과 문서화

- 각 분류의 구성과 분석 내용을 사용자에게 확인받는다. 사용자는 분류 합치기, 나누기, 자료 이동, 특징 수정과 제외를 할 수 있다.
- 일부 분류만 확인받았다면 그 분류만 확정한다. 나머지는 대화와 `PROGRESS.md`에서 미확인 상태로 구분한다.
- 해당 분류를 확인받은 뒤 `illustrations/<확인된-분류명>/STYLE.md`를 작성한다. 확인되지 않은 분류 폴더와 확정 분석 문서를 먼저 만들지 않는다.
- 확인된 분류를 기록하는 작업은 이 절차에 포함되므로 별도 저장 승인을 다시 받지 않는다.

`STYLE.md`에는 다음 내용을 기록한다.

- 분류명과 사용자 확인 상태.
- 레퍼런스 번호, 파일명 또는 접근 가능한 출처.
- 어떤 기준으로 묶고 다른 분류와 나누었는지.
- 관찰한 시각적 특징과 사용자에게 확인받은 해석.
- 반영할 특징과 제외할 특징. 미정인 사항은 미정으로 표시.
- 불확실한 부분, 복수 분류 참조 관계가 있다면 그 이유.
- 사용자가 무엇을 확인했는지 알 수 있는 발언 요지와 확인 날짜.
- 이후 변경 사항과 변경에 대한 사용자 확인.

새 레퍼런스 때문에 기존 분류를 바꿀 필요가 생기면 변경안을 먼저 보여준다. 이전에 확인된 기준을 임의로 바꾸지 않는다.

## 4. 선택한 스타일과 구도 구체화

- 기존 스타일을 선택하면 해당 `STYLE.md`를 읽는다. 말로 기획한 새 그림은 사용자가 확인한 설명을 브리프의 기준으로 삼는다. 여러 스타일을 결합하려면 결합할 요소를 사용자에게 확인받는다.
- 사용자가 설명한 구도를 정리하고, 제작에 필요한 내용이 빠졌다면 질문한다.
- 확인할 항목은 대상과 개수, 동작과 시점, 배치와 잘림, 배경, 색감, 필요한 여백, 이미지 비율과 사용 목적 등이다. 현재 작업에 필요한 항목부터 묻고 이미 정해진 내용은 재질문하지 않는다.
- 속지에서 활용할 때 필요한 조건은 확인하되, 이 단계에서 속지 전체 디자인까지 작업 범위를 넓히지 않는다.
- 에이전트가 충분하다고 판단해서 다음 단계로 넘어가지 않는다. 정리한 구도와 다음에 만들 프롬프트의 범위를 사용자에게 확인받는다.

작업이 생기면 해당 스타일 폴더의 `works/<작업명>/BRIEF.md`에 확인된 요청, 미정 사항, 확인 근거를 기록한다. 제안을 확정 내용과 섞지 않는다.

## 5. 미드저니 프롬프트 작성과 확인

- 사용자와 확인한 스타일과 구도를 기준으로 프롬프트를 작성한다. 합의되지 않은 디테일이나 다른 스타일을 임의로 추가하지 않는다.
- 사용자에게 한국어로 의도를 설명하고, 미드저니에 넣을 실제 프롬프트와 옵션을 함께 제시한다.
- 사용하는 미드저니 버전과 기능을 확인하고 그 버전에서 유효한 옵션만 제안한다. 불확실한 문법이나 지원 여부는 확인이 필요한 것으로 표시한다.
- 스타일 참고 이미지와 구도 참고 이미지의 역할을 구분한다. 사용자가 승인한 용도와 범위로 사용한다.
- 사용자에게 프롬프트와 옵션을 전달한다. 이미지를 참조할 경우 그 용도를 명시하고 시험 생성 범위를 사용자와 정한다.
- 해당 작업의 `PROMPT.md`에 버전별 프롬프트, 옵션, 참조 자료와 사용자 확인 상태를 기록한다. 수정 전 프롬프트도 보존한다.

## 6. 시험 생성, 결과 확인, 수정과 확장

- 사용자가 합의한 수량으로 미드저니에서 시험 생성하고 검토할 결과를 전달한다. 결과 수령 전에는 프롬프트 전달까지만 완료로 기록한다.
- 에이전트는 받은 이미지에서 스타일, 구도, 반영하거나 제외할 특징을 확인한다. 재생성 시 유지하고 싶었던 부분까지 달라질 수 있으므로 실제 결과를 비교한다.
- 사용자가 수정을 요청하면 유지할 부분과 바꿀 부분을 구분해 프롬프트를 고친다. 속지에서 채택한 그림의 형태를 그대로 써야 하면 해당 원본을 직접 배치한다.
- 이후 추가 제작, 확대, 배경 정리, 최종 사용용 파일 제작은 각각 사용자가 확인한 범위 안에서 진행한다.
- 작업의 `RESULTS.md`에 실제 결과 파일이나 접근 가능한 링크, 확인 가능한 작업 식별자, 사용한 프롬프트 버전과 옵션, 사용자 피드백 및 채택 상태를 기록한다. 확인할 수 없는 값은 만들지 않는다.

## 파일 구조와 다음 단계 전달

분류와 실제 작업이 생길 때 필요한 항목만 만든다.

```text
illustrations/
├── AGENTS.md
├── references/                  # 제공된 원본을 보관할 필요가 있을 때 생성
└── <확인된-분류명>/
    ├── STYLE.md
    └── works/
        └── <작업명>/
            ├── BRIEF.md
            ├── PROMPT.md
            ├── RESULTS.md
            ├── source/          # 생성 원본과 수정 원본
            └── exports/         # 확인된 사용용 결과물
```

사용자가 채택한 일러스트와 해당 스타일, 파일 경로, 사용 조건, 미정 사항을 기록하여 속지 작업에 전달한다. 속지 작업을 자동으로 시작하지 않는다. 파일 이동이나 이름 변경 시 관련 참조 경로도 함께 갱신한다.
