# 속지 디자인에서 미드저니 활용하기

## 목적과 역할

미드저니를 속지의 색감, 분위기, 장식과 전체 배치 방향을 탐색하는 데 활용한다. 시안을 확인한 뒤 실제 기록에 필요한 문구, 표, 치수와 출력 조건을 편집 단계에서 완성한다.

사용자와 실시간으로 대화하며 진행하고, 저장소 루트의 공통 행동규칙과 이 디렉토리의 `AGENTS.md`를 따른다. 사용자가 만족할 만큼 요청이 구체화되었음을 확인받고, 작은 중간 결과를 검토하면서 다음 단계로 넘어간다.

- 에이전트: 레퍼런스 분석, 요구사항과 배치 정리, 미드저니 프롬프트 및 설정 안내, 생성 결과 검토, 수정안과 후속 편집 준비.
- 사용자: 단계별 방향 확인, 미드저니에서 실제 생성, 결과 전달과 채택 여부 결정.
- 최종 편집: 합의한 도구로 실제 일러스트 원본, 정확한 문구와 표, 치수와 출력 조건을 반영한다. 도구와 실행 수단을 확인한 뒤 에이전트와 사용자가 맡을 범위를 정한다.

현재 합의한 실행 방식은 에이전트가 프롬프트를 제공하고 사용자가 미드저니에서 생성하는 것이다. 계정이나 브라우저 제어권한만으로 자동 생성이 가능하다고 가정하지 않는다. 향후 실행 방식을 변경하려면 공식 지원 여부와 실제 도구를 확인하고 사용자와 합의한다.

## 어떤 작업에 적합한가

아래는 이 프로젝트에서의 활용 권장 범위이며, 생성 결과의 정확성을 보장하는 표가 아니다.

| 작업 | 활용 방식 |
| --- | --- |
| 색감, 분위기, 장식 스타일 탐색 | 여러 시각적 방향을 비교하는 데 활용 |
| 배경, 패턴, 테두리 제작 | 장식 요소 후보를 만들고 사용자가 검토 |
| 일러스트와 기록 공간의 배치 | 전체 배치를 검토할 시안으로 활용 |
| 정확한 한글 문구, 금액과 날짜 | 별도 편집을 권장하고 최종 내용을 직접 검수 |
| 정확한 칸 수, 간격, 실측 크기와 타공 여백 | 편집 도구에서 확정하고 검수 |
| 채택한 일러스트의 원본을 그대로 사용 | 원본 파일을 직접 배치하는 방식을 우선 검토 |

글자나 정확한 격자가 거의 없는 장식형 속지는 생성 이미지를 규격에 맞춰 바로 활용할 수도 있다. 이 경우에도 이미지 품질, 실제 크기와 사용자 확인을 거친다. 표, 금액, 날짜가 중요한 속지는 시안을 바탕으로 별도 편집하여 완성하는 방식을 권장한다.

## 레퍼런스와 일러스트 사용

- 여러 레퍼런스를 한 번에 받았다고 해서 같은 디자인 방향으로 취급하지 않는다.
- 각 자료에서 색감, 장식, 표 구조, 배치 중 무엇을 참고할지 구분하여 사용자에게 확인받는다. 서로 다른 자료의 요소를 결합할 때에도 결합 범위를 확인한다.
- 일러스트를 사용할 경우 해당 작업에 있는 스타일 문서 또는 브리프와 채택 결과 기록을 읽고 사용할 실제 파일과 버전을 확인한다.
- 일반 이미지 프롬프트와 스타일 레퍼런스는 새 이미지를 만드는 참고 자료이다. 확정한 그림이 동일한 형태로 보존되어 배치된다고 보장하지 않는다.
- 참고 이미지로 새 구성을 생성하는 작업과 원본 일러스트를 직접 배치하는 작업을 구분한다. 캐릭터의 형태나 기존 그림을 그대로 유지해야 하면 원본을 직접 배치하는 방식을 권장한다.
- 미드저니의 편집 기능을 활용하는 경우에도 결과를 원본과 비교한다. 사용한 기능의 이름만으로 원본 보존을 확인했다고 처리하지 않는다.
- 그림 자체를 바꿔야 하면 변경 범위를 먼저 확인하고 일러스트 작업으로 연결한다.

## 단계별 작업 흐름

### 1. 참고 이미지 받기와 작업 조건 확인

먼저 사용자가 모아 둔 속지 참고 이미지를 10장 정도 요청한다. 이미 자료를 받았다면 제공된 이미지부터 살펴본다. 그다음 속지 용도, 실제 크기와 방향, 페이지 수, 인쇄 여부, 기록 항목 등에서 아직 정해야 할 것만 필요할 때 하나씩 묻는다.

필요한 재단, 타공, 양면 출력 조건과 사용할 편집 도구, 수정 가능한 원본 및 최종 파일 형식도 해당 단계 전에 확인한다. 아직 정하지 않은 항목은 미정으로 남기고 현재 단계에 필요한 질문부터 한다. 예시 규격이나 에이전트의 추천을 확정 조건으로 취급하지 않는다.

사용자가 요청과 다음 단계의 범위를 확인하면 진행한다. 표나 저축 챌린지에는 항목 누락, 칸 수와 목표 금액의 합계 등 필요한 검증을 포함한다.

### 2. 참고 요소와 배치 방향 확인

레퍼런스 분석과 기록 내용을 바탕으로 제목, 일러스트, 기록 공간의 위치와 비중을 제안한다. 필요하면 간단한 배치 시안을 먼저 보여준다.

여러 장의 속지도 대표 한 장으로 방향을 맞춘 뒤 확장한다. 사용할 일러스트가 아직 없으면 사용자 확인을 받아 자리표시자로 검토할 수 있다. 자리표시자를 사용한 시안을 최종본으로 처리하지 않는다.

처음부터 그림 없이 만들기로 한 속지는 사용자가 제공한 디자인 레퍼런스를 살펴본다. 예를 들어 “이 표의 줄 간격만 참고해”라고 하면 줄 간격을 참고하고 나머지는 해당 속지의 기록 내용에 맞춰 정한다. 배치가 확인되면 5단계에서 직접 편집할 수 있다. 3~4단계는 미드저니 시안을 요청한 경우에 적용한다.

### 3. 미드저니 시안용 프롬프트 작성과 확인

확인된 내용만 반영하여 프롬프트를 작성하고, 한국어로 의도를 설명한다. 사용자에게 다음을 함께 전달한다.

- 미드저니에 입력할 실제 프롬프트.
- 어떤 이미지를 어떤 참고 용도로 넣을지.
- 사용할 버전에서 유효한 비율과 생성 옵션.
- 사용자와 합의할 시험 생성 수량.
- 이번 시안에서 확인할 요소와 후속 편집에서 완성할 요소.

실제 속지의 배치를 검토하려면 원근 없는 정면의 평면 디자인을 요청한다. 책상 위 제품 사진이나 원근이 있는 목업이 목적이라면 별도로 합의하고, 그것을 인쇄 원본으로 간주하지 않는다.

정확한 문구나 칸 수를 프롬프트에 적어도 결과가 그대로 구현된다고 보장하지 않는다. 필요하면 기록 공간을 비워 두고 문구와 표는 편집 단계에서 넣는 방향을 제안하여 확인받는다.

프롬프트, 참고 자료의 역할, 옵션과 시험 범위를 사용자에게 확인받은 뒤 실제 생성 단계로 넘어간다.

### 4. 사용자 생성과 결과 검토

사용자가 미드저니에서 생성한 결과를 전달하면 실제 이미지를 확인한다. 결과를 받기 전에는 생성 완료나 품질 검토 완료로 기록하지 않는다.

전체 분위기, 색감과 장식, 일러스트 배치, 필기 공간, 불필요한 요소를 함께 검토한다. 새로 생성된 그림이 확정 원본과 달라진 부분도 구분한다.

사용자의 피드백을 받아 유지할 부분과 바꿀 부분을 정리한다. 수정 프롬프트와 다음 시험 범위를 확인받으며 진행하고, 확인 없이 반복 생성이나 대량 작업으로 확대하지 않는다.

시안 채택은 디자인 방향에 대한 확인이다. 시안 채택만으로 문구, 치수, 출력 품질까지 확인되었다고 처리하지 않는다.

### 5. 실제 속지로 편집

채택한 시안을 바탕으로 합의한 편집 도구에서 실제 문구와 숫자, 표, 선, 여백과 치수를 완성한다. 원본을 유지하기로 한 일러스트는 해당 파일을 직접 배치한다.

가능한 도구와 형식에서는 일러스트, 제목, 표와 기록선을 각각 수정할 수 있게 구성한다. 도구가 지원하지 않는 편집 가능 원본 형식을 제공한다고 약속하지 않는다.

한글 문구, 금액과 날짜, 표의 행·열 수, 칸의 간격과 합계를 확인한다. 실제 크기에서 글씨를 쓰기 편한지, 장식이 기록 공간을 가리지 않는지도 검토한다. 필요한 변경안을 보여주고 사용자에게 확인받는다.

### 6. 출력 검토와 최종 확인

최종 파일은 합의한 실제 크기, 방향, 여백과 출력 조건을 기준으로 검토한다. 이미지 비율을 맞춘 것만으로 실측 크기까지 맞았다고 처리하지 않는다.

이미지의 픽셀 수와 실제 배치 크기를 함께 보고 출력에 충분한 해상도인지 판단한다. DPI 숫자만 바꾸어 원래 이미지의 세부 정보가 늘었다고 설명하지 않는다. 모든 작업에 동일한 해상도나 여백 수치를 임의로 적용하지 않는다.

파일에서는 페이지 실측 크기, 글자와 여백, 타공 예정 위치를 검수한다. 실물 확인이 필요하면 사용자가 대표 한 장을 실제 크기(100%)로 출력해 색감, 타공 위치와 필기감을 확인한다. 전달받은 차이를 반영하고 파일 검수와 시험 출력 결과를 구분해 기록한다.

사용자가 최종 결과를 확인하면 합의한 파일 형식으로 정리한다. 여러 규격이나 변형 제작은 별도로 확인받은 범위에서 진행한다.

## 기록과 다음 대화에서 이어가기

- 작업별로 확인된 요구사항, 사용한 일러스트와 레퍼런스, 프롬프트 버전과 설정, 생성 결과, 채택 이유와 수정 내역을 기록한다.
- 디자인 방향 확인, 편집 내용 확인, 최종 출력 확인을 구분하고 미정 사항을 남긴다.
- 실제 작업이 생기면 해당 작업 안에서 `source/`에 생성 원본과 편집 원본을, `exports/`에 확인된 사용용 결과물을 보관한다. 이전 버전을 보존한다.
- `PROGRESS.md`에 현재 단계, 마지막 사용자 확인, 대기 중인 자료와 다음 행동, 관련 문서 경로를 남긴다.
- 새 대화에서는 공통 지침, 속지 지침, 이 문서와 해당 작업 기록을 읽고 마지막으로 확인된 단계부터 이어간다.

## 공식 기능 참고 자료

아래는 이 대화에서 확인한 공식 안내이다. 버전별 기능과 제공 조건은 실제 프롬프트를 작성하는 시점에 다시 확인한다.

- [문자 생성](https://docs.midjourney.com/hc/en-us/articles/32502277092109-Text-Generation): 짧은 문구와 라틴 문자에 가장 잘 맞는다는 안내.
- [이미지 프롬프트](https://docs.midjourney.com/hc/en-us/articles/32040250122381-Image-Prompts): 이미지를 참고하여 새로운 결과를 생성하는 방식.
- [스타일 레퍼런스](https://docs.midjourney.com/hc/en-us/articles/32180011136653-Style-Reference): 색감, 매체와 질감 등 스타일을 참고하는 기능.
- [크기와 해상도](https://docs.midjourney.com/hc/en-us/articles/33329374594957-Image-Size-Resolution): 픽셀 크기와 인쇄 크기, 해상도의 관계.
- [편집기](https://docs.midjourney.com/hc/en-us/articles/32764383466893-Editor): 이미지 이동, 크기 조정과 부분 편집 등의 기능.
- [공식 연동 및 자동화 안내](https://docs.midjourney.com/hc/en-us/articles/32013696484109-Community-Guidelines): 일반 API 제공과 승인되지 않은 자동화에 관한 안내.
